Privacy policy

This policy describes the current personal-use version of Wei Personal Assistant, operated by Wei for the owner's own accounts.

1. Google access and purpose

The assistant uses Google OAuth and does not ask for the owner's Google password. It requests these read-only scopes:

  • https://www.googleapis.com/auth/gmail.readonly — monitor new inbox messages and provide recent-mail queries.
  • https://www.googleapis.com/auth/calendar.events.readonly — read events and changes in the owner's primary Google calendar.

The Gmail scope permits reading message contents, but the current automated monitor and inbox query request metadata rather than full message bodies. The monitor processes identifiers, labels, sender, subject and snippets returned by Google. Recent-mail queries display up to five subjects and senders. Calendar monitoring processes event identifiers, titles, times and change status; day queries use the owner's configured time zone.

2. Storage and security

Google OAuth tokens, synchronization state, selected metadata and task records are stored on the owner's Oracle Cloud server. Tokens are kept in protected runtime files and are excluded from public source packages and this website. Google API requests use HTTPS. The assistant's administrative service remains private.

3. Sharing and model processing

Notifications are sent only to the owner's bound Telegram private chat. Telegram receives the notification content, such as mail sender and subject or an event title and time. Bot chats are not end-to-end encrypted. Google and Oracle Cloud process data as part of providing authentication, APIs and hosting.

Current Gmail and calendar monitoring and queries do not automatically transmit Google user data to Kimi or OpenAI. Other text tasks explicitly submitted to the assistant may be processed by those model providers. The application does not sell Google user data, use it for advertising, or use it to train general-purpose AI models.

Wei Personal Assistant's use and transfer of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements. This statement does not mean the app has completed Google's public verification.

4. Retention and deletion

Tokens are retained while the Google connection remains enabled. Saved metadata, synchronization state, notes and task records currently remain until the owner deletes them; a unified automatic expiry policy has not yet been implemented.

The owner can revoke access through Google Account connections. Revocation stops future authorized reads, but does not itself erase records already stored on the server or messages already delivered to Telegram. To delete stored assistant data and credentials, contact the operator below. Telegram copies must be deleted separately in Telegram. Server data deletion is currently performed by the operator rather than a public self-service form.

5. This public website

This static website has no Google sign-in, application database, advertising, analytics scripts, tracking pixels or input forms. If published using the proposed GitHub Pages hosting, GitHub may process ordinary visitor connection information, including IP addresses, under its privacy statement. No assistant mailbox records, calendar entries, chat records or credentials are published here.
